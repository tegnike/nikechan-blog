# 画像の作り方

3つの図それぞれに、PC用（横長）とスマホ用（`-mobile`、4:3か縦長）の2枚がある。
記事では `![代替](…/01-text-memory-flow.png){mobile=…/01-text-memory-flow-mobile.png}` と書き、画面幅640px以下でスマホ用に切り替えている。

| 図 | PC用 | スマホ用 |
|---|---|---|
| テキスト記憶の流れ | `01-text-memory-flow.png`（1600×612） | `01-text-memory-flow-mobile.png`（1560×1198） |
| MemTの記憶の流れ | `02-memt-memory-flow.png`（1600×612） | `02-memt-memory-flow-mobile.png`（1560×1198） |
| ベンチマーク別の得点 | `03-benchmark-gap.png`（1600×1040） | `03-benchmark-gap-mobile.png`（1000×1482） |

01と02は同じ型の対になる図。PC用どうし、スマホ用どうしで「文脈」「モデル」「回答」を同じ横位置に置き、章をまたいで見比べられるようにしている。

共通の調子: 論文やドキュメントの図のような、落ち着いた技術図。可愛さ・キャラクター・ロボット・装飾イラスト・アイコンは入れない（データベースの円柱と格子記号だけ可）。白背景、濃紺の太い日本語ゴシック体、細いグレーの角丸枠、青い矢印、薄い青のチップ。オレンジは「記憶の行列」だけに使う。指定した文字だけを正確に表示し、凡例、ロゴ、透かしを入れない。

## thumbnail.png「履歴をネイティブモデルに記憶するってどう言うこと？」

生成方法: Codex内蔵の imagegen。参照画像は3枚（`claude-code-workstyle-book-review/thumbnail.png` をデザインの手本に、公式三面図 `nikechan-model-sheet.png`、MemT-1.0公式バナー）。1732×908で生成し、1200×630へ縮小した。初版はタイトルを白い箱と黄色の決め文句に分けていたが、1つの文として読めるよう、同じ書体の2行にまとめる修正を1回かけている

考え方: 1秒で伝わることを優先し、要素を4つ（背景・タイトルの箱・ロゴのカード・ニケちゃん）に絞る。タイトルは見た目を途中で変えず、1つの文として読ませる。図、箱、舞う紙、吹き出し、機械的な背景、浮かぶ「？」は置かない。

```text
【サイズ】1200×630px（OGP標準）。上下の端に重要な要素を置かない
【デザインの手本】Claude Code本のレビュー記事のサムネイル。明るい単色の背景、太い黒文字の白い角丸の箱、黄色や赤の集中線、左下に傾けた「物」のカード、右に白いふちどりの大きなちびキャラ。文言・本・ポーズはまねない
【1. 背景】鮮やかなロイヤルブルーの単色。ごく薄い斜めの帯だけ可
【2. 左上〜左中央】幅の左62%ほどに白い角丸の箱。タイトル全体を2行で入れる。2行とも同じ極太の黒いゴシック体、同じ大きさ。1行目「履歴をネイティブモデルに」、2行目「記憶するってどう言うこと？」。「ネイティブモデル」だけ赤ピンクで、ほかはすべて黒。黄色のポップな文字は使わない
【3. 左下】タイトルの箱の下に、数度傾けた横長の白い角丸カード。左にMemTのロゴ（青い組み紐のマーク）、右に「MemT-1.0」を1行で、公式バナーどおりに入れる。カードの周りとニケちゃんの近くに、黄色と赤の集中線を少し
【4. 右38%】AIニケちゃん。頭の大きいちびキャラ、白い太いふちどり、上半身。公式三面図どおりの外見（紫のポニーテール、金色のAIヘアピン、茶色の目、青緑のAITuber Tシャツ、水色地にピンク水玉のパーカー、白いショートパンツ）。ポニーテールは三面図より少し短め。両手のひらを上に向けて肩をすくめ、首をかしげ、片方の眉を上げた「どういうこと？」の身ぶり。こちらを見ている
【文字】「履歴をネイティブモデルに」「記憶するってどう言うこと？」と、カードの MemT-1.0、ヘアピンの AI、Tシャツの AITuber だけ。ほかの文字、透かし、ほかのロゴ、ほかのキャラクターは入れない
```

## 01-text-memory-flow「テキスト記憶の流れ」

生成方法: Codex内蔵の imagegen
置き場所: 「AIの記憶は、ほとんどが「文章の出し入れ」」の章

### PC用

```text
【図解タイプ】横1列の処理フロー図（16:9で生成し、上下の余白を切って1600×612にした）
【見出し】左上に「テキスト記憶（RAGなど）」
【流れ】「会話の履歴」→ 円柱「外部に保存」（小さく「文章・ベクトル」）→「質問のたびに検索」→ 枠「文脈」（中に「今の質問」「見つけた文章」の2つ）→「モデル」→「回答」
【下の1行】「履歴が増えるほど、保存量も文脈も増える」
```

### スマホ用

```text
【図解タイプ】2段組みの処理フロー図
【キャンバス】4:3。幅350px前後に縮んでも読めるよう、文字は箱に入る最大の大きさにする。小さい文字は置かない
【見出し】左上に「テキスト記憶（RAGなど）」
【1段目】「会話の履歴」→ 円柱「外部に保存」（小さく「文章・ベクトル」）→「質問のたびに検索」
【折り返しの矢印】「質問のたびに検索」の下から出て、段の間を左へ進み、2段目左端の「文脈」の上へ入る。「モデル」「回答」には触れない
【2段目】枠「文脈」（中に「今の質問」「見つけた文章」の2つ）→「モデル」→「回答」
【下の2行】「履歴が増えるほど、」「保存量も文脈も増える」
【仕上げ】生成後に白い余白を56pxずつ足した
```

## 02-memt-memory-flow「MemTの記憶の流れ」

生成方法: Codex内蔵の imagegen（同じ向きの01を参照画像にして、大きさ・余白・文字・線・箱の位置をそろえた）
置き場所: 「MemTは、記憶をモデルの中に置く」の章

### PC用

```text
【図解タイプ】01のPC用と同じ型の処理フロー図（同じ範囲で上下の余白を切って1600×612にした）
【見出し】01と同じ位置に「MemTの記憶」
【流れ】01で「会話の履歴」「外部に保存」「質問のたびに検索」があった左側は空ける。01と同じ位置に枠「文脈」（中に「今の質問だけ」の1つ）→ 青枠「モデル」（中にオレンジの「記憶の行列」、小さく「大きさは一定」。そこから出力側へ短い矢印「生成中に読み出す」）→「回答」
【戻りの矢印】「回答」の下から「記憶の行列」の下へ戻る青い矢印。下に「ターンの終わりに書き込む」、小さく「消去・書き込み・忘却」
【下の1行】「元の文章は文脈に残さない」
```

### スマホ用

```text
【図解タイプ】01のスマホ用と同じ型の処理フロー図
【キャンバス】01のスマホ用と同じ4:3。文字の大きさも同じ
【見出し】01と同じ位置に「MemTの記憶」
【3列】01の2段目と同じ横位置・幅で「文脈」「モデル」「回答」を置く
  - 左: 枠「文脈」（中に「今の質問だけ」の1つ）
  - 中央: 青枠の縦長の枠「モデル」。中の下側にオレンジの「記憶の行列」（小さく「大きさは一定」）。その上に、上向きの短い矢印と「生成中に読み出す」
  - 右: 「回答」
【矢印】「文脈」→「モデル」→「回答」
【戻りの矢印】「回答」の下から出て、左へ曲がり、「記憶の行列」の右側へ入る。横に「ターンの終わりに書き込む」、小さく「消去・書き込み・忘却」
【1段目】01にあった保存と検索の箱は描かない。その高さは縦長の「モデル」に使う
【下の行】「元の文章は文脈に残さない」
【仕上げ】生成後に白い余白を56pxずつ足した
```

## 03-benchmark-gap「ベンチマーク別の得点」

生成方法: 画像生成は使わず、論文の表3の数値からSVGを描いてPNGにした（数値と位置を正確にするため）
置き場所: 「成績は、まだテキスト記憶に届いていない」の章
元データ: MemT-1.0 技術レポート（arXiv:2610.26825）表3。MemOSはNemotron土台の行

```bash
rsvg-convert -w 1600 03-benchmark-gap.svg -o 03-benchmark-gap.png
rsvg-convert -w 1000 03-benchmark-gap-mobile.svg -o 03-benchmark-gap-mobile.png
```

- 形式: 行ごとに2点を線で結ぶ図。行は11個のベンチマークで、履歴の長さごとに4つに分ける
- PC用は履歴の長さを左の列に、スマホ用は見出しの帯にしている
- 色: MemOSはオレンジ `#eb6834`、MemT-1.0-Proは青 `#2a78d6`
- 右端の列: 差（Pro − MemOS）
- 修正するときはSVGを直して上のコマンドで書き出す

論文にも同種の図（Figure 1）があるが、11個中6個だけで文字も小さいため使っていない。
