こんにちは、ニケです。

私はこれまで、Cursor、Claude Code、Codexと主力の開発ツールを何度か変えてきました。
過去のnoteとXを調べ直すと、新しいものへ順番に乗り換えたというより、その時の困りごとを一番うまく解決するツールへ移っていたようです。

ざっくりまとめると、次のような流れでした。

| 時期 | 主な開発ツール | 変わった理由 |
|---|---|---|
| 2023年10月〜 | Cursor | コードをAIへ渡す手間を減らし、Chatから自走型の開発へ進めた |
| 2025年5月〜 | Claude Code | 難しい実装の成功率と、CursorのCPU負荷を含む運用面 |
| 2025年8〜10月 | Codexをメイン寄りで併用 | 当時の安定性とコーディング性能 |
| 2025年11月〜 | Claude Codeへ回帰 | Claude Code側の性能向上 |
| 2026年3〜4月〜現在 | Codex | Codex Appの操作体験、長いタスク、スマホ連携 |

こうして並べると、主軸は**CursorからClaude Code、そしてCodexへ**移っています。
ただし実際には一直線ではなく、Claude CodeとCodexの間を一度往復していました。

## Cursor導入直後の衝撃

Cursorを使い始めたのは2023年10月末です。
最初に試したのは、業務で初めて触る言語を使ったTODO APIの作成でした。

当時のNew AI Projectへ短い指示を出すと、5〜10分ほどで一通りのファイルが生成されました。
エラーは残ったものの、CursorのAI Chatへそのまま渡して修正し、出力時間を含めて30〜40分ほどで動作確認まで進んでいます。
このとき私自身はコードを一切書いていませんでした。

初めて触る言語でも、生成からエラー修正までAIと進めれば動くものを作れる。
この最初の体験は、当時のnote「CursorにTODOアプリ作ってもらった」に残しています。

https://note.com/nike_cha_n/n/n9a467559f7c8

約1か月後に書いた「Cursor歴1ヶ月の私がよく使う機能を紹介する」では、VSCodeとChatGPTを併用していた頃との違いを**質問するまでの手間が段違いに少ないこと**と整理しています。
選択したコードやターミナルのエラーをショートカットでChatへ送り、`@ファイル`、`@フォルダ`、`@Docs`、`@Codebase`で必要な情報を追加できる。
今見ると素朴な機能ですが、ブラウザへコードを何度も貼る作業がなくなるだけで、開発体験は大きく変わりました。

https://note.com/nike_cha_n/n/nfcd5292b2359

もちろん、最初から何でも快適だったわけではありません。
使い始めて約10日で月500回のfast requestを使い切り、混雑時にはslow requestで10〜30秒ほど待つこともありました。
プロジェクト全体を雑に渡すと関係ないコードが増えて回答精度が落ち、APIキーを使えば費用も膨らみます。

この頃からすでに、AIへ大量のコードを渡せばよいのではなく、**必要なコンテキストだけをどう選ぶか**が重要だと考えていました。

## AI ChatからComposer Agentへの変化

2024年3月の「CursorとClaudeを使った最近の私の開発環境」では、普段の開発はCursor、難しい問題や大量のコードはブラウザ版Claudeという分業を紹介しています。
Cursorは必要なファイルをすぐ指定できる一方、Claudeは長いコンテキストと回答性能に強い。
後のClaude Codeへの移行より前から、エディタの操作性とモデルの性能を分けて使っていたことになります。

https://note.com/nike_cha_n/n/n444e28ec0c73

2024年9月、利用開始から約1年の時点では、まだAI Chatが中心でした。
当時のComposerは会話の途中へ戻れず、複数ファイルの変更もタブをまたいで確認する必要があったため、まとめてApplyしがちになるのが自分の開発スタイルに合わなかったからです。

ところが2025年2月には評価が完全に逆転しています。
Chatはほぼ使わなくなり、コード変更やエラー対応、コマンド実行まで進めるComposer Agentが中心になりました。
Rules for AI、Project Rules、YOLOモード、Restoreなどを組み合わせ、Cursorを「質問するエディタ」ではなく**自走する開発エージェント**として使うようになっています。

この変化をまとめた「私のシンプルCursor活用方法」を読み返すと、同じCursorを使い続けていても、実際の開発方法はかなり変わっていたことが分かります。

https://note.com/nike_cha_n/n/nd0f7566019ae

## Cursorを主軸にしたAIツールの分業

2025年5月の「私が使ってるAIツールを紹介する」では、コードの80%ほどをCursorが書き、上位モデルの従量課金を含めて月$50〜70前後を使っていると振り返っています。
Claude 3.5 Sonnetに加えてo3も使い、以前のモデルでは解けなかった課題が一度で終わる場面も増えていました。

https://note.com/nike_cha_n/n/n6b2c5720832c

ただし、すべてをCursorだけへ任せていたわけではありません。
当時は複数のAIへ次のように役割を分けていました。

- **Cursor**: 単一機能の追加や日常的なコード修正
- **Cline**: UIやドキュメントなど、単純だけど広範囲な修正
- **Devin**: 機能追加の叩き台、不具合調査、非同期で進めたいタスク
- **CodeRabbit**: プルリクエストのレビュー

Clineは途中で止まることやAPI費用が気になり、主力にはなりませんでした。
Devinは初月に22セッションを動かして8件のPRがマージされましたが、難しい実装より叩き台や調査で力を発揮する「AIジュニアエンジニア」という感覚でした。

CodeRabbitは開発するAIではなくレビュー担当です。
これらは順番に乗り換えたツールではなく、Cursorを中心に開発工程を分業するための補助役でした。

Cursorは短期間だけ試したツールではありません。
約1年半の間に、コードをAIへ渡す窓口から、実装の大部分を任せる主力へ育っていったツールでした。

## Claude Codeを選んだ理由

Claude Codeを使い始めたのは2025年5月23日です。
切り替えた理由は、**難しいタスクを解決できる確率が高かったから**でした。
CursorやDevinで手戻りしていたタスクがClaude Codeでは一度で終わるなら、CLI中心で少し使いにくくてもこちらを選びます。

この切り替え時の比較は、「私のシンプルなClaude Codeの使い方」に詳しく書いています。

https://note.com/nike_cha_n/n/nee3503e7a617

Cursorから離れた理由は、Claude Codeの性能だけではありません。
Cursorは更新のたびにCPU負荷が気になるようになり、最終的には軽いVSCodeとClaude Codeの組み合わせへ移行しました。

後に2025年の振り返りでも、Cursorの機能ではなくCPU負荷がVSCodeへ戻る理由だったと書いています。

つまり、Cursorが役に立たなくなったというより、実装の成功率とエディタの負荷を合わせて考えた結果です。
Cursorが解決したのは「AIへコードを渡す手間」でしたが、Claude Codeが減らしたのは「実装が失敗してやり直す手間」でした。

## CodexとClaude Codeの間を往復

2025年8月ごろからCodexを使う割合が増え、10月には「安定しすぎていて離れられる気がしない」と書くほど評価していました。
新機能の多さよりも、長いタスクを最後まで安定して進められることが魅力でした。

ところが1か月ほどで状況が変わります。
当時のCodexは履歴や周辺機能が少なく、使い続けるほど不便も見えました。
一方でClaude Code側の実装性能が戻ったと感じ、11月末にはCodexをほとんど使わない状態まで戻っています。

2025年末には、私自身も「途中Codexなどに浮気もしたが、Claude Code一筋」と振り返っていました。

一度決めた評価が数か月後も続くとは限らない。
この往復は、AI開発ツールの変化の速さをそのまま表しています。

## Codex Appによる開発環境の変化

2026年3月、久しぶりにCodexを使うと、単純なコーディング性能の強さに驚きました。
4月からメインとして試し、最終的に定着した大きな理由は**Codex Appの操作体験**です。

複数のタスクを別スレッドで動かし、完了したものを順番に確認する。
画像生成やブラウザ操作も同じ場所から依頼し、PCのエディタやターミナルを開かずスマホからもアクセスできる。

6月には、しばらくエディタもターミナルも開かず、Codex Appだけで作業する状態になっていました。
これはモデルを入れ替えたというより、開発を始める場所そのものが変わったという感覚に近いです。

Cursorが「エディタの中でAIと開発する」体験、Claude Codeが「CLIのAIへ実装を任せる」体験だとすれば、現在のCodexは**複数の開発タスクを管理する場所**に近いです。

## 現在の主力はCodex

2026年7月28日時点ではCodexが主力です。
Claude CodeのMaxプランも終了する予定ですが、図解やスライドのデザインなど、Claudeの方が向いていると感じるタスクでは今も使っています。

今回振り返って分かったのは、特定の会社やモデルではなく、開発で一番面倒な部分が変わるたびに主力ツールも変わってきたことでした。

- Cursorは、AIへコードを渡す手間を減らした
- Claude Codeは、難しい実装の手戻りを減らした
- Codexは、複数タスクを動かして管理する手間を減らした

数か月後にはまた別のツールを使っているかもしれません。
だから今は、どのAIが最強かを決めるより、Claude CodeとCodexをいつでも切り替えられるように、ルールやドキュメントをプロジェクト側へ残しておく方が大事だと思っています。
