## AIの記憶は、ほとんどが「文章の出し入れ」

前提として、LLMそのものは会話をまたいで何かを覚えているわけではありません。
覚えているように見えるのは、過去の内容を毎回プロンプトへ入れ直しているからです。

入れ直し方は、大きく3つあります。

- **全部入れる**: これまでの会話をそのままプロンプト（文脈）に載せる
- **要約して入れる**: 長くなった履歴を短い文章にまとめて載せる
- **探して入れる**: 履歴を外部のデータベースに保存し、関係のある部分だけ検索して載せる（RAG）

Mem0やMemOSのような記憶の仕組みも、保存や検索の工夫はさまざまですが、最後は文章としてモデルへ渡します。
AIニケちゃんの記憶も同じで、会話や人物の情報を文章で保存しておき、必要なときに取り出す方式です。

こうした文章ベースの方式は、レポートでは「テキスト記憶」と呼ばれています。「探して入れる」流れを図にすると、次のようになります。

![テキスト記憶の流れの図。会話の履歴を文章やベクトルとして外部に保存し、質問のたびに検索して、今の質問と見つけた文章を文脈に入れ、モデルが回答する。履歴が増えるほど、保存量も文脈も増える](/static/images/posts/memt-native-memory/01-text-memory-flow.png){mobile=/static/images/posts/memt-native-memory/01-text-memory-flow-mobile.png}

この方式は中身を人間が読めて、間違いを直しやすいのが長所です。
一方で、履歴が長くなるほど保存量や文脈が膨らみ、検索で取りこぼした情報はなかったことになります。

## MemTは、記憶をモデルの中に置く

MemT-1.0は、この「文章を渡す」部分をなくそうとしています。

過去の会話は、モデルの内部にある**記憶用の行列**へ書き込まれます。
書き込みが終わると、元の文章は文脈から消してしまいます。
次の質問には、過去の文章を読み直さず、行列から読み出した情報を使って答えます。

先ほどと同じ形で描くと、次のようになります。

![MemTの記憶の流れの図。文脈に入るのは今の質問だけで、モデルの中にある大きさが一定の記憶の行列から生成中に読み出して回答する。ターンの終わりに、消去・書き込み・忘却のゲートで行列へ書き込む。元の文章は文脈に残さない](/static/images/posts/memt-native-memory/02-memt-memory-flow.png){mobile=/static/images/posts/memt-native-memory/02-memt-memory-flow-mobile.png}

テキスト記憶の図では、文脈に「今の質問」と「見つけた文章」の両方が入っていました。
MemTの文脈に入るのは「今の質問」だけで、過去の情報はモデルの中から直接読み出されます。

モデルカードには、子猫の名前や年齢、好物を伝えたあとに会話履歴を0件にし、それでも「子猫は何歳？」に答えられる例が載っています。
記憶はファイルに保存でき、別のセッションで読み込めば続きから使えるようになっています。

もう少し中身を書くと、次のような作りになっています。

- 土台は既存の公開モデルで、その重みは変更しない
- いくつかの層に記憶用のブロックを足し、通常の注意機構の出力へ、記憶から読み出した値を加える
- ターンが終わるたびに、消去・書き込み・忘却の3つのゲートで行列を更新する

記憶のたびにモデルを再学習するわけではありません。
書き込みは、文章を1回モデルに通すだけで済みます。

公開されたのは次の3モデルです。

| モデル | 土台 | 全体のパラメータ | 記憶の大きさ |
|---|---|---:|---:|
| MemT-1.0-Nano | Qwen3.6-35B-A3B | 36B | 40MiB |
| MemT-1.0-Flash | DeepSeek-V4-Flash | 288B | 1280MiB |
| MemT-1.0-Pro | NVIDIA Nemotron 3 Ultra | 554B | 48MiB |

記憶の大きさは、記憶ブロックを足した層の数や行列サイズの違いによってモデルごとに異なります。

## 履歴が伸びても、記憶は大きくならない

テキスト記憶との一番の違いは、**記憶の大きさが一定**なことです。
会話が1万トークンでも100万トークンでも、Proなら48MiBのまま変わりません。

| | テキスト記憶 | MemTの記憶 |
|---|---|---|
| 置き場所 | モデルの外（文章やベクトル） | モデルの中（行列） |
| 履歴が伸びると | 保存量も文脈も増える | 記憶の大きさも文脈も増えない |
| 思い出し方 | 検索して文脈へ入れる | 生成中にそのまま読み出す |
| 中身の確認 | 人間が読める | 人間には読めない |

レポートでは、一番小さいNanoを使って速度と保存量を測っています。

- 履歴が128Kトークンのとき、全文方式のKVキャッシュを丸ごと保存する場合に比べて、保存量は約66分の1
- 質問から最初のトークンが出るまでの時間は、256Kトークンまで伸びても約104〜112msでほぼ一定（全文方式は256Kトークンで約445ms）
- 履歴の準備まで含めた全体の時間は、全文方式に比べて128Kトークンで約1.86倍、256Kトークンで約3.99倍速い

ただし、短い履歴では全文方式のほうが速く、追いつくのは32Kトークンあたりからです。
長く付き合うほど得をする仕組みですね。

## 成績は、まだテキスト記憶に届いていない

では、肝心の「ちゃんと覚えているか」はどうでしょうか。

レポートでは、11個の記憶ベンチマークで各手法を比較しています。
テキスト記憶の行は、Proと同じNemotronを土台にしたときの平均点です。

| 方式 | 手法 | 平均 |
|---|---|---:|
| テキスト記憶 | MemOS | 72.08 |
| テキスト記憶 | 全文を文脈に入れる | 66.17 |
| テキスト記憶 | 単純なRAG | 59.06 |
| モデル内の記憶 | MemT-1.0-Pro | 53.08 |
| モデル内の記憶 | MemT-1.0-Flash | 50.60 |
| モデル内の記憶 | MemT-1.0-Nano | 46.97 |
| モデル内の記憶 | 他手法の最良（Temp-LoRA） | 38.08 |

モデルの中に記憶を持つ方式どうしで比べると、MemTの3モデルが上位を独占しています。
しかしテキスト記憶と比べると、単純なRAGにもまだ届きません。

一番上のMemOSは、同じチームが開発しているテキスト記憶の仕組みです。
自分たちの既存の方式に負けている結果も、そのまま載せています。

このMemOSとProの得点を、11個のベンチマークごとに並べたのが次の図です。
レポートの表3の数値から作りました。

![11個のベンチマークについて、MemOSとMemT-1.0-Proの得点を履歴の長さ別に並べた図。差が大きいのはLongMemEval-Sの46.80点、Memoraの36.94点、BEAM-1Mの35.96点で、PS-BenchだけはProが6.54点上回っている](/static/images/posts/memt-native-memory/03-benchmark-gap.png){mobile=/static/images/posts/memt-native-memory/03-benchmark-gap-mobile.png}

差が大きいのは、長い履歴から細かい事実を引く課題です。
LongMemEval-Sでは、MemOSの80.60点に対してProは33.80点でした。
逆に、ペルソナに基づいて応答するPS-BenchではProが99.03点で、同じ土台のテキスト記憶（91〜95点台）を上回っています。

この弱点については、著者自身もレポートの中で限界として挙げています。
記憶の大きさが一定なので、新しい情報を入れるほど、古い細部が失われていくためです。

なお、冒頭のX投稿にあった「BEAM-1Mで+4.76点」「MemoryAgentBenchで+6.51点」は、テキスト記憶ではなく1つ下のFlashと比べた数字です。
11個のうちProがFlashを上回ったのは5個で、残りの6個はFlashのほうが上でした。

## それでも面白いと思う理由

結果だけ見ると「まだ使えない」で終わりそうですが、私はかなり面白い方向だと思っています。

1つ目は、**細部よりも「身についたこと」に向いていそうな点**です。
レポートでは、コーディングエージェントに過去の成功手順を記憶させる実験をしています。
SWE-bench Verifiedで、3回試してすべて解けた課題の割合は54.00%から61.60%に上がりました。
同じ手順を文章で渡した場合も61.60%です。
手順やコツのような情報なら、文章で持たなくても同じくらい効くことになります。

2つ目は、**まだ伸びしろが残っている点**です。
Nanoで記憶の容量を4倍にした実験では平均が46.97点から48.11点に上がり、同じデータで追加学習を2周目まで続けても得点は伸びていました。
モデルの大きさや学習データとは別に、「記憶の容量」という伸ばし方が増えたわけです。

3つ目は、**テキスト記憶と組み合わせられる点**です。
実際、先ほどのエージェントの実験でも、手順の検索は外部で行い、選んだものをモデル内の記憶へ書き込んでいます。
いつ何があったかという事実は文章で持ち、相手との距離感や仕事の進め方のような傾向はモデルの中に持つ、という分担はありえそうです。

AIニケちゃんの記憶で今困っているのは、必要な情報を取り出すまでに時間がかかることです。
履歴がどれだけ増えても応答の速さが変わらない記憶は、常駐するAIキャラクターにとってかなり魅力的に見えます。

Proは554Bパラメータなので、個人で動かすのは現実的ではありません。
個人で試すなら、全体で36B、推論時に使うのは3B分のNanoになります。

現時点では、テキスト記憶の置き換えというより、記憶の持ち方がもう1つ増えたと受け取るのが良さそうです。
